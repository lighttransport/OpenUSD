# Custom Namespace Build for USD v24.11

This document describes how to build USD v24.11 with a custom Python package name (e.g., `pxr_lte`) to enable side-by-side installation with another USD build.

## Summary

The custom namespace build allows you to:
- Install USD with a different Python package name (e.g., `pxr_lte` instead of `pxr`)
- Use a different C++ namespace (e.g., `pxr_lte` instead of `pxr`)
- Use a different library prefix (e.g., `lte_` instead of `usd_`)
- Import both standard USD (`pxr`) and custom namespace USD (`pxr_lte`) in the same Python process

## Key CMake Options

| Option | Description | Example |
|--------|-------------|---------|
| `PXR_SET_EXTERNAL_NAMESPACE` | C++ namespace for USD symbols | `pxr_lte` |
| `PXR_LIB_PREFIX` | Prefix for library names | `lte_` |
| `PXR_PYTHON_PACKAGE_NAME` | Python package directory name | `pxr_lte` |

## Build Procedure (Windows)

### Prerequisites

- Visual Studio 2022 with C++ workload
- Python 3.11+ (via uv or other installer)
- TBB (pre-built or from source)
- CMake 3.20+

### Step 1: Clone and Checkout v24.11

```bash
git clone https://github.com/PixarAnimationStudios/OpenUSD.git
cd OpenUSD
git checkout v24.11
```

### Step 2: Apply Custom Namespace Patches

The following files need to be modified to support custom Python package names:

1. **cmake/defaults/Options.cmake** - Add `PXR_PYTHON_PACKAGE_NAME` option
2. **cmake/macros/Private.cmake** - Patch Python source files to use custom import paths
3. **cmake/macros/Public.cmake** - Patch moduleDeps.cpp to register modules with custom package name
4. **cmake/macros/patchModuleDeps.py** - Helper script for patching moduleDeps.cpp

### Step 3: Configure CMake

```bash
mkdir build-lte
cd build-lte

cmake .. ^
    -G "Visual Studio 17 2022" ^
    -A x64 ^
    -DCMAKE_INSTALL_PREFIX=C:/path/to/dist-usd-lte-v24.11 ^
    -DPXR_SET_EXTERNAL_NAMESPACE=pxr_lte ^
    -DPXR_LIB_PREFIX=lte_ ^
    -DPXR_PYTHON_PACKAGE_NAME=pxr_lte ^
    -DTBB_ROOT_DIR=C:/path/to/tbb ^
    -DPXR_BUILD_IMAGING=OFF ^
    -DPXR_BUILD_USD_IMAGING=OFF ^
    -DPXR_BUILD_USDVIEW=OFF ^
    -DPXR_BUILD_TESTS=OFF ^
    -DPXR_BUILD_EXAMPLES=OFF ^
    -DPXR_BUILD_TUTORIALS=OFF ^
    -DPXR_ENABLE_MATERIALX_SUPPORT=OFF
```

### Step 4: Build and Install

```bash
cmake --build . --config Release --parallel
cmake --build . --config Release --target install
```

## Usage

### Python Import

```python
import sys
import os

# Add DLL directories (Windows Python 3.8+)
os.add_dll_directory(r'C:\path\to\dist-usd-lte-v24.11\lib')
os.add_dll_directory(r'C:\path\to\dist-usd-lte-v24.11\bin')
os.add_dll_directory(r'C:\path\to\tbb\bin')

# Add Python path
sys.path.insert(0, r'C:\path\to\dist-usd-lte-v24.11\lib\python')

# Import custom namespace USD
from pxr_lte import Usd, Sdf, Tf

# Check version
print('USD version:', Usd.GetVersion())  # (0, 24, 11)
```

### Same-Process Dual USD

You can import both standard USD and custom namespace USD in the same Python process:

```python
import sys
import os

# Setup paths for pxr_lte
os.add_dll_directory(r'C:\path\to\dist-usd-lte-v24.11\lib')
os.add_dll_directory(r'C:\path\to\dist-usd-lte-v24.11\bin')
sys.path.insert(0, r'C:\path\to\dist-usd-lte-v24.11\lib\python')

# Import both
from pxr import Usd as PxrUsd      # Standard USD (e.g., from pip)
from pxr_lte import Usd as LteUsd  # Custom namespace USD

print('pxr version:', PxrUsd.GetVersion())
print('pxr_lte version:', LteUsd.GetVersion())
```

## Technical Details

### What Gets Patched

1. **Python source files** (`__init__.py`, etc.):
   - `from pxr import` → `from pxr_lte import`

2. **C++ moduleDeps.cpp files**:
   - `TfToken("pxr.Tf")` → `TfToken("pxr_lte.Tf")`
   - This ensures `TfScriptModuleLoader` registers modules with the correct package name

### Why moduleDeps.cpp Patching is Needed

In v24.11, `moduleDeps.cpp` files contain hardcoded `pxr.` prefixes for Python module registration:

```cpp
TfScriptModuleLoader::GetInstance().
    RegisterLibrary(TfToken("tf"), TfToken("pxr.Tf"), reqs);
```

Without patching, importing `pxr_lte.Usd` would fail because the loader would look for `pxr.Tf` instead of `pxr_lte.Tf`.

### Differences from dev Branch

The dev branch uses a template-based approach (`moduleDeps.cpp.in` + `genModuleDepsCpp.cmake`) to generate moduleDeps.cpp at configure time. The v24.11 branch uses build-time patching via `patchModuleDeps.py` because the source structure is different.

## Files Modified

- `cmake/defaults/Options.cmake` - Added `PXR_PYTHON_PACKAGE_NAME` option
- `cmake/macros/Private.cmake` - Added Python source file patching
- `cmake/macros/Public.cmake` - Added PYTHON_CPPFILES moduleDeps.cpp patching
- `cmake/macros/patchModuleDeps.py` - New helper script for C++ patching

## Troubleshooting

### Import Error: "No module named 'pxr'"

If you see an error like `ModuleNotFoundError: No module named 'pxr'` when importing `pxr_lte`, it means the Python source files weren't properly patched. Check that:
1. The `PXR_PYTHON_PACKAGE_NAME` CMake option is set
2. The build completed successfully with "Patching __init__.py for custom package name" messages

### Import Error: Module dependency issues

If you see errors about missing modules like `pxr.Tf`, it means the moduleDeps.cpp files weren't properly patched. Check that:
1. The `patchModuleDeps.py` script exists in `cmake/macros/`
2. The build shows "Patching moduleDeps.cpp for custom package name" messages
3. The patched files contain `pxr_lte.` instead of `pxr.`

### DLL Not Found (Windows)

Use `os.add_dll_directory()` to add the library paths before importing:
```python
import os
os.add_dll_directory(r'C:\path\to\dist-usd-lte-v24.11\lib')
os.add_dll_directory(r'C:\path\to\dist-usd-lte-v24.11\bin')
os.add_dll_directory(r'C:\path\to\tbb\bin')
```
